### Reproducibility — the one non-obvious call
You asked for `UNIFORM`/`NORMAL`/`RANDOM(seed)`. Problem: `RANDOM(seed)` is only deterministic *per evaluation order*, and Snowflake parallelises `GENERATOR` scans, so which row gets which draw can shift between runs. Bit-identical rebuilds need randomness derived from the row's own identity.

So the engine is four deterministic UDFs in `RAW`, built on `HASH(seed, salt, row_id)`:

| UDF | Purpose |
|---|---|
| `RND(key)` | uniform [0,1) |
| `RND_INT(key, lo, hi)` | uniform integer |
| `RND_NORM(key, mean, sd)` | normal, via Irwin–Hall sum of 3 independent draws |
| `RND_PICK(key, array)` | weighted-ish categorical pick |

`SEED` is a single literal at the top of `03`. Same seed → byte-identical tables, every run, regardless of cluster size. `UNIFORM`/`NORMAL` still appear where the draw feeds a value nothing joins on. I'll document this trade-off in a header comment rather than leave it implicit.

### Ground truth drives the data, not the reverse
`RAW.CUSTOMER_SEGMENT_TRUTH` is generated **first**; every other generator reads it and conditions its output on it. That's what makes the planted predicates fire with exact counts instead of hoping random draws collide.

It lives in its own table, not as a `CUSTOMER` column, so the NBA engine physically cannot use it as a feature — only `evals/` reads it. This is my one addition to your entity list.
